# 当日の進め方

審査は **3 分間のデモンストレーション**。評価は 4 点。

| 審査基準 | このリポジトリでの対策 |
| --- | --- |
| テーマに沿っているか（**事前の作り込みは評価されない**） | 事前準備は配線と土台だけに留めてある。機能は当日ゼロから作る |
| 実装度（**提出URLで動くこと**を重視） | main にマージ = 自動デプロイ。`/api/health` でいつでも生存確認できる |
| チャレンジ精神 | ここは当日の企画次第 |
| AI 活用度 | `server/routes/chat.ts` が最初から通っているので、AI を組み込む所からすぐ始められる |

---

## タイムライン

### T+0:00 — テーマ発表
**すぐコードを書き始めない。** まず「3 分のデモで何を見せるか」を 1 文で決める。
デモの絵から逆算して、そこに必要なものだけを作る。

### T+0:15 — 設計を 2 人で確定（15分で切り上げる）
1. 画面を 2 つ（多くても 3 つ）に割り、**どちらが何を作るか**を決める
2. `src/shared/types.ts` に**フロントとサーバーの契約**を書く ← 2人で一緒に書く
3. `CONTRIBUTING.md` の担当表を埋める
4. ここまでを **1 コミットで main に直接入れて push**（この 1 回だけ直 push でよい）

これ以降、**型ファイルを 2 人で同時に触らない状態**を作るのが目的。

### T+0:30 — 並行開発開始
- 各自 `feat/<自分>/<機能>` ブランチ。担当ディレクトリの外は触らない
- 30 分ごとに PR → CI 通過 → プレビューURLで確認 → セルフマージ
- AI に投げるときは「このディレクトリの中だけ」と毎回言う

### 残り 2:00 — 機能追加を止める
ここから先は**新機能を作らない**。統合・デバッグ・見た目の調整だけ。
「あと 1 個作れる」は大体作れない。

### 残り 1:00 — 本番URLを確定させる
- main にマージし、本番デプロイが緑になったことを確認
- **シークレットウィンドウ**と**スマホ**で本番URLを開き、通しで動かす
- ここで動いていれば、最悪この後何が起きても提出物は成立する

### 残り 0:30 — デモのリハーサル
- 3 分で回るシナリオを 1 回通す。喋る担当と操作する担当を決める
- 「最初の 30 秒で何が見えるか」がすべて。ローディングで 30 秒使わない
- 失敗しがちな操作（音声入力、ファイルアップロード等）は代替手段を用意しておく

### 残り 0:10 — 提出
本番URL（`https://xxx.up.railway.app`）を提出。PR 環境の使い捨て URL と間違えない。

## 事故ったときの対処

| 症状 | 対処 |
| --- | --- |
| 本番が壊れた | Railway の Deployments で前のデプロイを **Redeploy**（30秒で戻る） |
| コンフリクトが解けない | 10 分粘って無理なら自分の変更を捨てて書き直す。`git switch main && git switch -c feat/...` |
| ビルドが通らない | `npm run check` をローカルで実行。CI と同じことをしている |
| `/api/chat` が 500 | `/api/health` の `hasApiKey` を見る。false なら Railway の Variables が未設定 |
| デプロイ成功なのに開けない | Railway で **Generate Domain** を押していない（公開URLが存在しない） |
| 最初の1回だけ 502 | Serverless(App Sleeping) が ON。OFF にする |
| 本番に変更が反映されていない気がする | `/api/health` の `commit` を見る。自分の push の SHA と一致するか |
| 画面が真っ白 | ErrorBoundary が入っているのでエラー文が出るはず。出ないなら main.tsx より前で落ちている |

## デモで効く小ネタ

- **初期状態でいきなり何か見えている**こと。空の入力欄だけの画面は 3 分の審査で不利。
  サンプル入力をあらかじめ入れておく
- AI の応答は**ストリーミングで文字が流れる**だけで「動いている感」が出る（`server/routes/chat.ts` は対応済み）
- 審査員が自分で触る前提。**説明なしで押せるボタン**にする
- ネットワークが不安な会場では、**事前に本番URLをスマホで開いておく**
